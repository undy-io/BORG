# BORG v0.3.0

Release date: July 31, 2026

## Highlights

- Adds optional versioned request-event logging with `noop` as the default sink
  and Kafka as the first external sink.
- Filters accepted requests by principal, model, and request headers, with
  configurable request/response body and privileged header capture.
- Preserves per-request ordering and supports session-based Kafka partitioning,
  bounded event sizes, explicit truncation metadata, and byte reconstruction.
- Supports Kafka TLS, client certificates, PLAIN, SCRAM-SHA-256, and
  SCRAM-SHA-512 with Kubernetes existing-Secret wiring through Helm.
- Keeps logging fail-open and independent of proxy responses and readiness,
  including during broker outages, queue saturation, and shutdown loss.

## Compatibility

- The default `noop` configuration preserves the BORG `v0.2.0` proxy behavior.
- Request-event schema version remains `1`.
- Kafka topics remain operator-managed; BORG does not create or administer
  topics.
- Captured headers and bodies are privileged data and may contain credentials,
  personal data, or proprietary model input and output.

## Validation

- Go tests, race tests, vet, golangci-lint, strict Helm validation, and shell
  syntax checks passed during milestone completion.
- The raw-WSL Kafka acceptance passed against the pinned Apache Kafka 4.2.1
  image with TLS, SCRAM-SHA-256, normal and SSE reconstruction, broker outage,
  restart, and retained delivery.
- Both GitHub-hosted integration jobs passed: the logging-enabled KinD deployment
  path and the direct TLS/SCRAM Kafka recovery path.

See [`../request-logging.md`](../request-logging.md) for configuration, event
semantics, operational safeguards, and consumer reconstruction guidance.
